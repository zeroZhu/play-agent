# 破阵设宴、门客设宴任务流程

## 代码边界

- `PZSY_task.py`：破阵设宴任务，类名 `PZSYTask`，任务键 `PZSY`。
- `MKSY_task.py`：门客设宴任务，类名 `MKSYTask`，任务键 `MKSY`。
- `banquet.py`：两类设宴任务共用的八槽位提交、物品获取、购买确认和开始设宴逻辑。
- `run_queue.py`：扫描 `*_task.py` 并通过 `task_key` 建立任务队列。加载过程不依赖具体 Python 类名，因此类名缩写不会影响已保存的 `PZSY`、`MKSY` 队列状态。

## 主流程

```text
任务启动与界面清理
  -> 打开“活动-帮派”
  -> 定位破阵设宴/门客设宴入口并点击“前往”
  -> 在邀约列表选择一个可邀约目标并等待自动寻路完成
  -> NPC 对话中点击“邀请赴宴”并确认
  -> 进入设宴物品面板
  -> 依次处理 8 个物品槽位
  -> 检查“开始设宴”按钮亮度
  -> 按钮可用时点击并处理确认弹窗
  -> 回到“活动-帮派”验证是否完成
  -> 记录任务收尾结果
```

如果打开邀约列表后已经处于物品面板，任务会跳过“选择目标、自动寻路、NPC 邀约”，直接从八槽位物品处理继续。

## 八槽位物品处理

两个任务按相同坐标依次处理 8 个槽位。每个槽位只处理一次，顺序如下：

1. 如果存在“一键提交”，点击后处理下一个槽位。
2. 否则，如果存在“获取”，打开获取途径面板。
3. 按顺序尝试获取途径：
   1. 推荐帮派仓库：存在可提交物品时提交并返回设宴面板。
   2. 商城：点击购买，按需处理购买确认弹窗，再返回设宴面板。
   3. 摆摊：先尝试本服商品，再尝试全服商品，购买成功后返回设宴面板。
4. 商城或摆摊购买后如果仍显示“获取”，判定本次购买异常，重新点击“获取”并按完整优先级再尝试一次。
5. 再次获取后仍显示“获取”时只记录异常，不再继续重试，随后处理下一个槽位。
6. 获取成功并返回后，再尝试一次“一键提交”。
7. 所有受支持途径均失败时记录日志，返回设宴面板并继续下一个槽位。

摆摊购买采用严格确认：确认弹窗最多点击 3 次且必须消失；仍未消失时尝试取消，并保存调试截图后抛出异常，避免误判购买成功。

购买异常重试同时覆盖商城、本服摆摊和全服摆摊；帮派仓库提交成功不执行该检查。额外获取只允许一次，避免单个物品槽位无限循环。

## 开始设宴与完成判定

“开始设宴”不只依赖模板匹配，而是读取按钮区域平均亮度：

| 任务 | 亮度阈值 | 面板识别补充条件 |
| --- | ---: | --- |
| 门客设宴 | 150 | 获取、一键提交或可用的开始设宴按钮 |
| 破阵设宴 | 120 | 获取、一键提交、5 道菜页签或 6 道菜页签 |

破阵设宴的 5/6 道菜页签目前只用于识别物品面板，不会主动切换页签；物品提交统一处理 8 个槽位。

按钮亮度不足时视为材料不齐，只记录“物品不足，跳过开始设宴”，不抛异常。按钮可用且点击成功后，任务会把 `_started_banquet` 标记为 `True`，用于收紧后续完成校验。

完成校验重新打开“活动-帮派”，判定规则如下：

- 活动入口已消失：完成。
- 入口存在但没有“前往”：视为当前无法继续邀约，结束校验。
- 进入后仍是物品面板，或仍存在可邀约目标：
  - 已点击过“开始设宴”：抛出异常，触发重试，避免把提交失败误判为完成。
  - 未点击过“开始设宴”：只记录未完成并结束，允许材料不足时队列继续执行。
- 进入后既不是物品面板，也没有可邀约目标：完成。

## 两类任务的分支差异

| 场景 | `PZSYTask` | `MKSYTask` |
| --- | --- | --- |
| 活动入口不存在 | 直接结束当前流程 | 跳转到 `verify_completion` 再校验 |
| 邀约列表没有“前往邀约” | 直接结束当前流程 | 跳转到 `verify_completion` 再校验 |
| 已在物品面板 | 跳转到八槽位处理 | 跳转到八槽位处理 |
| 正常提交后的校验 | 执行 `verify_completion` | 执行 `verify_completion` |
| 前台唤醒 | 延迟到 `on_start` | 使用通用启动时机 |

## 重试边界

- DSL 步骤的 `retry=N` 表示首次执行失败后最多再重试 `N` 次；例如 `retry=3` 最多执行 4 次。
- 打开活动、打开列表和选择目标等步骤配置了步骤级重试；选择目标步骤内部同时等待自动寻路完成。
- NPC 邀约不做步骤级重试：“邀请赴宴”等待 60 秒、确认邀约等待 10 秒、物品面板等待 30 秒，任一等待失败都会保存现场截图。
- 所有一梦江湖步骤级和任务级异常恢复都会先检查并唤醒省电模式，再执行现有识图脱离卡死；不发送返回键，也不执行未识别的兜底点击。
- 某一步在步骤级重试后仍失败，队列执行器会从任务开头重跑整套流程；每个任务最多执行 3 轮完整流程。
- 三轮仍失败时跳过当前任务，继续队列中的下一个任务。
